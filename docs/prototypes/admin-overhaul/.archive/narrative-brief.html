Angle · Narrative / Weekly Brief

bwell Admin — a paragraph, not a dashboard.

The admin home opens with a short written brief of the service this week. Numbers appear underneath as evidence, not as the main surface. The admin reads once, sees what moved, sees what needs a hand, and closes the tab. Pace is slow and ritualistic; the tone is a measured clinical newsletter, not an ops console.

Section 05 · Component breakdown

What it's made of

New components this design introduces

  • WeeklyBrief — the prose block. Accepts an ordered array of paragraph spans, each either plain text or a DrilldownPhrase. Handles the typewriter on first mount only.
  • DrilldownPhrase — a pressable span with a dotted teal underline. Bound to a type union ({ kind: 'outcome', instrument }, { kind: 'queue' }, etc.) so the inline-expansion target is typed at compile time.
  • InlineChart — 12-bucket bar chart sized to fit under a paragraph. Accepts an OutcomeResult[]; renders suppressed buckets as a hatched bar. No tooltip — the sentence above is the caption.
  • EvidenceStrip — three-cell numeric row. Each cell renders value, label, and optional delta vs prior-period. A thin wrapper around the existing StatStrip.
  • BriefArchiveRow — archive list row. Title + two-clause summary + chevron. Tap reopens that week's prose.
  • StaleBriefBanner — the error state. Shows the brief timestamp + links to /admin/system/health.

Existing bwell components reused

  • ContentContainer — screen wrapper with header, for the /admin/home route.
  • ThemedText — all typography. type="title" for "This week at bwell", type="default" for the prose paragraphs, type="small" for deltas & datelines.
  • TypewriterText — drives the first-paragraph reveal. Its imperative-handle API is a natural fit for the "wait, then start" cue from useAdminOverview.
  • StatStrip — underpins EvidenceStrip. No styling change; data is just three cells instead of four.
  • Collapsible — the inline chart expansion uses the same expand/collapse mechanics as existing sections.
  • ActionMenu — the queue row's "Verify" button opens it, with tier pick (cbt / pwp) and a confirmation step (variant: 'destructive' is not used — verify is constructive — but the confirm step is).
  • EmptyState — cold-start and error-state panels.
  • Chip / StatusChip — dateline pills, "2 overdue" pill, "LIVE / STALE" markers.
Back-end request

This design requires one new BE endpoint.

Option (a) chosen. Client-side templating from the existing AdminOverviewResponse would work for the trivial sentences (totals, deltas), but breaks on the interesting cases: conditional clauses ("no new stalled attempts since Monday" needs week-over-week delta of a count, which the current response doesn't carry), honest suppression phrasing ("we need twenty patients per instrument before we can report a rate"), and the archive ("reopening that Monday's brief exactly as it was written" requires the sentence to be persisted, not regenerated from today's data).

Ask: a new endpoint GET /api/admin/brief?week=<ISO-week> that returns the AdminOverviewResponse plus a brief: { paragraphs: Array<Array<Span>>; generatedAt: string; model: 'template-v1' | 'llm-gpt-…'; } field. Sentence assembly is a template pass on the BE by default; an LLM variant is opt-in behind a flag. The brief row is persisted at rollup time so the archive is a read, not a regeneration.

Why not just templating? Tried it in the design — the fourth sentence always reads like Mad Libs. Prose tone is load-bearing for this angle; it deserves a first-class BE surface.

Section 06 · Rationale

Why prose serves this admin

  1. The admin is non-clinical and non-continuous. They come in on Monday morning, they want to know what moved and what's stuck, and then they leave. A paragraph is a better interface for that cadence than a grid of twelve tiles — the admin reads the state of the service once instead of scanning for anomalies.
  2. Suppression is easier to explain in English than in a cell. "—" with a tooltip is hostile. "we need twenty patients per instrument before we can report a rate" is not. Because every OutcomeResult ships with n and reason, the BE can compose that sentence exactly — the FE never has to guess the threshold.
  3. Evidence sits below, not above. Numbers appear after the prose, never as the first thing — this deliberately avoids the Stripe / Mixpanel reflex of "big number → panic reaction". The sentence frames the number before the number is seen, which means the admin reads proportion, not magnitude.
  4. Queues surface via sentences, not red pills. "Two therapists have been waiting over seven days for verification" is how you'd tell a colleague. It avoids alert-fatigue (rule §4 anti-patterns) while still letting the amber tint + the verify button sit inline. The queue is an imperative verb in prose, not a status light.
  5. The archive is the killer feature. Briefs are persisted at rollup time. A trustee asks "what did we know on April 6th?" and the answer is a tap — opening week 14 shows exactly the sentence and numbers the admin saw that morning, even if the data has since shifted. This is hard to do with a reactive dashboard and cheap to do with persisted prose rows. It's also the only way this design is defensible against the "dashboard-as-export-trigger" anti-pattern — the brief is the export.
