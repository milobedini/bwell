Angle 04 · Split Command Centre

bwell Admin —
a command centre, not a dashboard.

One screen. Two panes. Everything the admin can touch — metrics, programmes, verification queue, stalled work, audit trail — lives in the left pane as rows. The right pane is the detail for whatever is highlighted. Clicks never navigate; they swap context. Keyboard-first, like Linear, Superhuman, Front.

bwell is RN-first with a web target. This angle is deliberately web-optimised: on desktop you get the full split; on mobile the two panes collapse into a familiar list → detail stack.

Section 05 · Components

What we reuse, what we build.

The split-command shell is new; everything that lives inside it is familiar bwell vocabulary.

New components (this angle)

  • AdminSplitShell The 56 / 380 / 1fr three-column grid with topbar. Web-only layout; on mobile renders as a stacked stack navigator.
  • UniversalListPane The left pane. Grouped virtualised list (FlatList on RN, windowed list on web). Renders rows for metrics, programmes, queue entries, audit events.
  • CommandRow Single row atom. Props: glyph, title, sub, right-slot, urgency, href. Owns focus, selected, and hover states.
  • DetailPane The right pane. Switches content by selected row kind. Crossfades on change. Crashes are scoped here, not globally.
  • CommandBar Topbar search + / hotkey binding. Fuzzy-search over the left-pane corpus.
  • ShortcutSheet The ? overlay. Reads from a single keymap registry.
  • SuppressedBar BarSparkline variant that renders hatched fill + a reason chip when suppressed === true. Never computes a rate.
  • InlineVerifyCard Renders inside DetailPane; picks tier, confirms, emits the audit event, auto-advances queue.
  • FreshnessChip Compact rollupAsOf display; goes amber past 24h.

Existing components reused

  • ThemedText All typography. type=title / subtitle / smallTitle / default / small / smallBold / link.
  • ThemedButton Primary / outline / error variants (verify, retry, open system health).
  • StatStrip Top of every DetailPane. Four-up KPI row — exact pattern from TherapistDashboard.
  • BarSparkline Module-type breakdown and care-tier bars.
  • Sparkline Inline outcome trend line.
  • Chip / StatusChip Care tier, freshness, suppression reason, audit outcome.
  • EmptyState Used inside DetailPane for zero-programme / zero-data states.
  • ActionMenu Row-level context menu (view user profile, open in audit, reject application) with destructive confirmation.
  • Container / ContentContainer Mobile fallback screens.
  • IconSymbol All glyphs on the rail + CommandRow.
Section 06 · Why this design

Rationale, in five bullets.

The brief asks for a first-class admin home. This angle commits to admin-as-fluent-operator.

01 · Context preservation beats navigation

Admin work is cross-referential — "look at Depression recovery, then the two unverified PWPs, then the audit of the last verification". A split layout keeps the spine of everything visible while the detail swaps. Clicking a programme never unloads the queue.

02 · The list is the source of truth

KPI grids hide relationships between items. A unified grouped list (attention → operational → programmes → audit) reads like a priority queue: urgent bubbles to the top, everything is enumerable and linearly scannable. /overview already returns all these groups in one call; the design collapses them into one list instead of four tiles.

03 · Keyboard-first rewards the fluent user

bwell's admin is a small, repeat user. Their hours-per-week with the app justify muscle memory. / + J/K + Enter makes triage 3–5x faster than clicking. Superhuman / Linear / Front all earn their fans this way.

04 · Suppression as a first-class visual

k-anonymity (<5) and min-N (<20) are not edge cases — the dev environment will hit them often. Hatched bars + explicit "below_min_n" chips honour invariant 4 without needing admin to read docs. The FE never divides anything itself.

05 · Mobile doesn't lie about the surface

Rather than a different IA, mobile collapses the same list into a stack route. Desktop-only features (keyboard hints, focus ring cursor, ? sheet) are hidden, not replaced with inferior mobile equivalents. The angle is honest about its best canvas.

BE assumption worth flagging. Two minor deltas vs §2 we'd need before shipping: (1) the left-pane unified list reads most rows from /api/admin/overview, but mixing audit entries into the same stream would benefit from a small recentAudit: AdminAuditEvent[] slice on /overview — today we'd need a separate /audit?limit=5 call on load; (2) inline verify auto-advance would benefit from PATCH /user/:id/verify returning the next oldest unverified therapist in one round-trip rather than two, to keep the flow snappy. Both are additive, not breaking.
