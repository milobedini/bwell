4 Two-tap verify. Tier picker inline (C or P). No modal round-trip.
5 Keyboard-first hinting. J/K to move, C/P to verify. Web admin feels like a terminal.
6 Toast-slab with Undo. 8-second window to reverse destructive or irreversible verifies.
7 Pulse dot. Teal = healthy rollup; amber = queue aging; never red for merely "data exists".

04 · MOTION

Four motion moments

Motion here is a confirmation language, not decoration. All animations gated behind prefers-reduced-motion.

1 · Ticket → resolved

3 therapists awaiting verify
Trigger: admin confirms an action. Motion: severity rail colour-shifts amber → green, tick fills, row slides right and fades over 320ms ease-out. Siblings collapse up via FLIP (200ms ease-in-out). Haptic: light success on iOS.

2 · "All caught up" reveal

Trigger: last queue item dismissed (counter reaches 0). Motion: teal bloom scales 0.6 → 1.0 over 420ms, two outward rings fan out at 30% opacity over 800ms. Reuses existing BloomBurst primitive. Copy: typewriter reveal of "All caught up." via TypewriterText.

3 · Keyboard focus

J K C P
Trigger: admin hovers a queue row on web. Motion: relevant key hints pulse to teal for 180ms, then return. Staggered 300ms between J/K/C/P on first arrival only. Re-surfacing the affordance without a permanent cheat-sheet.

06 · RATIONALE

Why this serves the angle

Five reasons this design commits to ops-queue-first instead of hedging toward a KPI grid.

01

Identity = "what needs me"

The headline says "6 items need you", not "30 patients". The admin's role is oversight and unblocking, not browsing. The dashboard's first sentence should echo the first question they ask.

02

KPIs are a footnote, not a hero

Totals live in a compressed four-cell row below the queue. They're present for context (a glance answers "is the platform roughly healthy?") but never distract from the action list. Anti-pattern avoided: metric soup at the top.

03

Calm, not loud

Severity lives on a 4px rail, not a neon banner. Only true verifications-aging past 7 days get red; everything else is amber or grey. PagerDuty energy, Linear tone.

04

Empty state = celebration, not refill

When the queue reaches zero we reveal a single bloom + "All caught up.", then downrank secondary surfaces into a quiet "If you want to peek" list. We borrow directly from Superhuman's clean-inbox moment. The screen refuses to invent work.

05

Non-clinical by construction

Drill-in roster shows identifiers, programme, care tier, age — never content. A visible "non-clinical view" footer reminds the admin (and any future auditor) of the invariant from §3.8 of the brief.

BE · ASK

What this design asks of the BE

This deck assumes GET /api/admin/overview returns enough already — it does. But to drive the queue sort server-side and avoid FE triage logic (see project rule: sort/filter on BE), we'd want either: (a) a new overview.actionQueue: Array<{ type, severity, age, count, deepLink }> pre-sorted field, or (b) an explicit oldestUnverifiedAgeDays so the client doesn't compute aging itself. Neither is blocking; both would tighten the contract.

Data-contract compliance notes. All numbers shown are derived from AdminOverviewResponse fields named in §2 of the brief: verificationQueue.count, work.stalledAttempts7d, work.orphanedAssignments, users.therapists.zeroPatients, users.total, users.therapists.total, users.newThisWeek, users.activeLast30d. No OutcomeResult rates are displayed on the home surface, so k-anonymity suppression (§3.3–3.4) is not triggered — rates appear only on the "Outcomes · 90d" drill-in, which lives outside this deck.

Accessibility. Severity is always encoded with colour + icon + copy. Lato contrast against #0c1527 is AAA for body copy and AA for 11–12px pill labels. All decorative motion wraps in @media (prefers-reduced-motion: reduce).
