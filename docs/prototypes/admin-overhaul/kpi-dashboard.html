Prototype 01 · Straight Read

KPI Dashboard

The canonical SaaS admin home — stacked cards: operational counts, programme outcome chips, verification queue, audit strip. Stripe-calm, Linear-quiet. Operational answers in a single scroll.

A bwell admin should glance, trust, and act — not browse. Numbers speak, care-safety guards them, and everything that needs a person is one tap away.

04 · MOTION

Animation callouts

Motion earns its place — each moment either reports a change or confirms an action. No decorative drift.
On mount · 600ms

KPI count-up

412

When a tile renders for the first time, the number eases in (scale 0.94 → 1 + opacity 0.6 → 1). Signals "fresh" without bouncing. Suppressed on refetch to avoid distracting re-reads.

On queue >0 · 2s loop

Pulse — pending action

18 to verify

Only the verification count pulses, and only when >0. A quiet way to say "this is the one thing waiting for you" without making the whole screen red.

On verify success · 320ms

Row translates left + fades as the mutation resolves. Optimistic — reverts on failure. Count decrements in the header inline. BloomBurst fires when the last row goes.

When navigating to a programme detail, the outcome line strokes in left→right, then the area fill eases up. Makes the trend readable as it draws — not a static reveal.

05 · COMPONENTS

Component breakdown

Mostly built from the existing inventory — the design's job is to place them, not reinvent them.

New (Admin-scoped)

  • AdminSignalBannerConditional top-of-screen banner, triage-prioritised (queue → stalled → orphaned). Hidden when all zero.
  • KpiTileSingle metric card: label + value + prev-period delta. Renders skeleton on loading, tolerates null.
  • ProgrammeOutcomeChipRate + n, with suppression-aware rendering ("Too few" / "Fewer than 20" / muted dash).
  • VerifyQueueRowAvatar + name/email + tier + ageing chip. Tappable → opens `VerifyTherapistSheet`.
  • VerifyTherapistSheetHalf-sheet with mandatory tier picker (cbt/pwp), confirm CTA, optimistic mutation.
  • AuditStrip / AuditEventRowCompact 5-event preview (overview) + full paginated list (audit screen).
  • PrivacyModeBadgeRenders "Live" vs "Dev mode" chip from `privacyMode` on every admin response.
  • RollupStalenessBannerSurfaces `rollupLastRun.status === 'failure'` with last-known-good timestamp.

Reused (from §6 inventory)

  • ContainerFull-bleed dark screen wrapper.
  • ContentContainerFor audit/programme detail screens that need headers.
  • ThemedTextAll typography — `title`, `smallTitle`, `default`, `small`, `link`.
  • ThemedButton`variant="default"` for primary verify confirm; `outline` for "Load more".
  • StatStripBase for the KPI grid — extended with a delta sub-row.
  • Chip / StatusChipUnderpins rate chips, ageing chips, privacy badge, filter chips.
  • EmptyStatePre-rollup and inbox-zero messages.
  • CollapsibleAudit event details drawer (opaque context field).
  • BloomBurstOne-shot celebration when queue clears to 0.
  • BarSparkline / SparklineTimeline + work-mix bars on programme detail.
  • ActionMenuRow long-press on audit / queue rows (e.g. "Copy event id", "Open user profile").
  • IconSymbolAll iconography — SF on iOS, Material fallback.
06 · RATIONALE

Why this design serves the angle

Straight read = zero ambiguity, zero learning curve, maximum merge-ability.
  1. One endpoint, one scroll. The overview card stack mirrors `GET /api/admin/overview` 1:1 — signals, operational, programmes, queue, audit. No client-side joins, no N+1. A bored admin on their phone at 9am can read it in 15 seconds and leave.
  2. Care-safety is the first-class UX, not a footnote. k-anonymity suppression gets first-class visual language (muted chip + reason copy), privacy mode is always in the header, and admins never see individual scores — only aggregates, counts, and queues. The design cannot accidentally expose a patient.
  3. Numbers with comparators, deltas not vanity. Every KPI shows this-week vs prev-week (the API provides both). No naked counts. Colour supports the delta; copy carries the meaning — works for colour-blind admins.
  4. One thing to do, visible at a glance. The verify queue is the only routinely-actionable surface for a bwell admin. It gets preview-on-home + one-tap verify-in-sheet + celebration-on-zero. Everything else is informational — the hierarchy reflects that.
  5. Quiet by default, loud when it matters. Teal is accent only. Red appears only when `stalledAttempts7d > 0`, `orphanedAssignments > 0`, or queue ageing exceeds 7 days. A clean system looks clean — no sparkline wallpaper, no forced drama.
BE change requests: none. This design is fully achievable with the contract documented in §2. Optional nice-to-have: `users.newLastWeek` is already present, but the overview tile's "vs prev" for `activeLast30d` uses `activeLast30dPrevious` as-is — no schema change required.
