bwell · Admin overhaul · Prototype

Compliance gauge

Admin as remediation, not reporting. A single composite score at the top, a short list of contributing factors underneath, nothing else above the fold. Borrows posture from Vanta, Linear's Projects health, Datadog's SLO banner: binary at the top, nuanced only when drilled-in.

The routine admin check-in should resolve in under ten seconds: "is anything broken? if so, what, and what's the fix?" Every surface area answers "is this OK?" and renders a concrete remediation path.

Composite score — derived from /api/admin/overview: the gauge counts four contributors, each tripped by one threshold from the existing response.
 
attention = verification.tripped + stalled.tripped + orphaned.tripped + rollup.tripped
verification.tripped = oldest queued therapist's createdAt is older than 7 days (from verificationQueue.oldest[0].createdAt)
stalled.tripped = operational.work.stalledAttempts7d > 5
orphaned.tripped = operational.work.orphanedAssignments > 0
rollup.tripped = rollupAsOf is null or older than 48h
 
Gauge band: 0 → green ("All clear"); 1–2 → amber ("Admin attention needed"); 3–4 → red ("Escalation — review now"). Day-one uses a fifth "unknown" state when rollupAsOf is null and no other item has tripped.

Component breakdown

New primitives are minimal — the gauge and the remediation row. Everything else reuses existing bwell inventory from §6 of the brief.

New components

  • <ComplianceGauge /> SVG ring with stroke-dashoffset. Props: trippedCount, totalChecks, state (green | amber | red | unknown | loading), headline, subcopy. State is computed upstream from the overview response, not inside the component.
  • <RemediationItem /> Row: glyph + title + value + description + CTA. Supports severity = success | info | amber | red. Glyphs bound to severity so colour-blind users see the same hierarchy.
  • <RemediationList /> Vertical stack of RemediationItems. Owns the four contributor slots in a fixed order so the gauge position always maps to the same row index.
  • <RollupFreshnessPill /> Shows "rolled-up Xm ago" at the top of the gauge card and as a pill in drill-down headers. Visible reminder that the admin is looking at aggregates, not live data.
  • <VerifyTierSheet /> Half-sheet over the queue. Therapist preview + CBT/PWP tier picker + Confirm. Built on @gorhom/bottom-sheet with keyboard-safe insets.

Reused from §6

  • ContentContainer Wraps the admin home at px-4.
  • ThemedText title / subtitle / smallTitle / small / smallBold — only typographic primitive.
  • ThemedButton default for "Verify", outline for dismiss.
  • Chip / StatusChip Drives the "dev mode" pill when privacyMode === 'reduced' and the threshold pills in drill-down headers.
  • ClientCard pattern Queue rows borrow layout (avatar · name · sub · right-aligned value) from the existing therapist dashboard.
  • ActionMenu For destructive paths (reject therapist, mark orphan as resolved) with built-in confirmation.
  • EmptyState For sub-screens like an empty audit log, not the gauge itself (which has its own "all clear" state).
  • StatStrip Secondary row at the bottom: 30d active · audit events · programmes. Quiet context, never primary.

Rationale

Five bullets on why this design serves the angle.

  • Binary at the top, nuanced on drill-in. One gauge, one number, one sentence. The admin answers "am I needed?" before they scroll. If zero, done. If non-zero, they drill into exactly the item that moved the count — a direct, lossless map from gauge to remediation.
  • Composite score is derivable from /overview today. Four contributors, each a hard threshold on one field the BE already returns (verificationQueue.oldest[0].createdAt, operational.work.stalledAttempts7d, operational.work.orphanedAssignments, rollupAsOf). No new BE surface required for the landing view — which is the point of this angle.
  • Anti–alert-fatigue by construction. Three colour bands (green / amber / red) but only red pulses, and only when first transitioning in. Amber is calm — a count, a row, a CTA. Green is muted — absence of problems shouldn't feel like a win condition. Each severity carries a distinct icon glyph (✓ ▲ ◆ ✕ !) so the list reads in greyscale.
  • Remediation framing, not reporting. Every row answers "is this OK? what's the fix?" The CTA is verb-led ("Resolve verify queue", "Notify therapists", "Reassign") and the drill-down lands on a surface where the admin can complete the task in one half-sheet — not three tabs deep. Resolved items stay visible as green ticks so the admin trusts nothing is hidden.
  • Honest about what's known. The rollup-freshness pill is surfaced everywhere, not buried. A fifth "unknown" state (dashed ring, "?") handles the day-one case when rollupAsOf === null — the gauge refuses to paint itself green without evidence, preventing a false all-clear. Privacy-mode (reduced) dev marker sits beside the gauge so staging is never confused with production posture.
BE change requests: none required for the landing gauge — every contributor is derivable from /api/admin/overview. To resolve the "stalled work → notify therapists" CTA in one tap, we'd want a POST /api/admin/attempts/:id/nudge endpoint that dispatches a therapist notification and logs an audit event. Likewise, a POST /api/admin/assignments/:id/reassign would close the orphan loop without a full client-side form. Both are follow-up endpoints, not blockers for this prototype.
